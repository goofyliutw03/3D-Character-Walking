# 環境雷達掃描設計

ViewerApp 從移動快照取得腳底座標，SceneRenderer 管理單次掃描的生命週期。EnvironmentScan 在活動期間走訪當前可見環境 Mesh，擴充 Three.js 相容的內建色彩材質。依既有頂點變形順序，在實例／批次矩陣及位移後取得世界座標。以三維歐氏距離計算波前與尾跡，每次繪製前共用時間及原點 uniform。直接在色彩 pass 上色，沿用相機、遮擋、透明度與後處理。水面自訂 shader 及環境之外的物件維持原本渲染。

編譯 hook 與快取鍵可還原，閒置時不走訪材質。掃描結束時恢復 hook，場景切換和 WebGL context loss 走同一清理路徑。回復功能時移除 button、事件、ViewerApp 觸發與 SceneRenderer 接點即可。

## 動態物件與波帶篩選（2026-11-22）

ViewerApp 明確傳入 Target 與已啟用的交通角色群組。活動時保留可見材質走訪，讓非同步換模、LOD 或透明遮擋切換即時納入。閒置時省略走訪。由 CPU 每幀計算一次波帶內外半徑的平方。GPU 使用點積篩選，僅在波帶內執行開根號、波形及混色。此法使用精確的球殼邊界，保留骨架動畫、GPU 位移、實例及批次幾何。物件級包圍盒剔除需要考慮骨架變形及共用材質，作為後續取得實測瓶頸後再評估的選項。

## 白青亮刃（2026-11-22）

在既有球殼分支內分離白青亮刃、青色波肩與餘光。以加法疊入線性色彩，保留原材質的細節與明暗變化，繼續由既有 tone mapping 處理亮度。亮刃輪廓約 0.21 m，波肩約 0.48 m，餘光於波後 3.4 m 內淡出。沿用深度遮擋、不透明度及魚眼／X-ray 的基礎場景繪製。首輪採固定世界寬度，待遠景量測再決定是否增加導數抗鋸齒。

## 首掃著色器生命週期（2026-11-22）

本節取代前述活動期間注入、清除時還原 hook、逐幀材質走訪的設計。材質使用單一可掃描色彩版本。按鈕只改原點、波帶與強度 uniform，強度為 0 時，頂點與片元跳過掃描運算，平方半徑篩選維持。採事件接上城市載入的建築、Target 新模型與交通重建，並在場景綁定及建立遮擋材質副本時一次準備。WeakSet 去重並避免留住離場材質。Context loss 清除強度，材質的 hook 由同一 CPU 資產保留，恢復後在正常繪製重編。銷毀時移除新增子樹的監聽。代價是可掃描版本於正常首次繪製時編譯，驗收以相同裝置對照首屏及首掃。

## 平行預編譯（2026-11-22）

預設 Needle 啟動前檢查 KHR_parallel_shader_compile。用獨立群組暫存可見的城市 MeshStandardMaterial 網格副本，共用 geometry 與 material，並以正式場景提供光源。避免來源子樹含燈光而使街燈在 Three.js compileAsync 內重複計數。引擎載入不等待預編譯完成，失敗回到正常繪製。此階段限初始城市材質及 Needle，從入口移除呼叫即可回復。

## 高密度點光源（2026-11-22）

在 Three.js 編譯參數具有至少 24 盞點光源且沒有點光陰影時，只替換 lights_fragment_begin 的點光源迴圈。沿用原本的光源順序、衰減與材質 BRDF，使用索引讀取一般點光源 uniform，保留其他光型的展開規則。有點光陰影或光源數較少時沿用 Three.js 原本的 chunk。材質註冊與掃描 hook 疊加，Caster 材質只註冊光源迴圈。魚眼、X-ray 和掃描共用這個材質色彩結果。回復時移除 PointLightShader 及其兩個接點。
